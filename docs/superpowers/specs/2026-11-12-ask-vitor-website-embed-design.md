# Ask Vitor on jvitorcosta.github.io: design

Date: 2026-11-12. Status: draft for Vitor's approval.

## Intent

Put ask-vitor on Vitor's personal website as an "Ask me" assistant. Visitors (mostly recruiters and
engineers, also friends) ask about his work, projects, education and life, and get short answers
grounded only in what he has published. It should feel like part of the site (a game dialogue,
not a generic chat widget), be easy to use, and be a clean, documented example of a careful LLM
product: no made-up facts, a fixed fallback, visible sources, guardrails, evals, cost limits.

Two audiences:

- **Visitors:** quick, honest answers about Vitor without reading the whole site.
- **Vitor's study and portfolio:** ask-vitor is his showcase and study repo. Every decision is
  written up there in plain language, as with `docs/streaming-and-web-ui.md`.

## Goals

- Answers about: professional experience (roles, responsibilities, first job, what he did where),
  projects and repos, education (where he studied), skills, and personal life (hobbies, sports,
  movies, music, travel, food, cars, tech tinkering).
- Live data stays fresh: recent songs, films, books, anime and activities, as the site already shows.
- Never invents facts. Unknown or off-limits questions get exactly
  `I don't have information about that.`
- Each answer shows its sources as tags (e.g. `[CV · Experience]`, `[Letterboxd · updated 2h ago]`).
- English and Portuguese, following the site's language switch.
- Cheap and abuse-resistant: hard monthly spend cap and per-visitor rate limit.

## Non-goals

- No retrieval / embeddings / vector store (whole knowledge file goes in the prompt; see below).
- No accounts, no chat history across visits, no multi-turn memory beyond the current dialogue.
- No new tracking on the site. No cookies.
- Not a general assistant: no coding help, no world knowledge.

## Anti-goals (failure even if it "works")

- It states something about Vitor that isn't in the knowledge file.
- It reveals anything on the never-share list, or helps someone locate him.
- It reads as if Vitor typed the answers himself.
- A visitor can run up the API bill or use it as a free general chatbot.
- It slows the page or breaks it when the API is down.
- It clashes with the site's look or its privacy and accessibility promises.

## Where it lives on the page (decided: option C + menu link)

- A **▶ ASK ME** button in the site's top bar (`<header class="top">`, next to the palette dots
  and the EN/PT button; my call, since the site has no menu) scrolls to the trainer card and opens
  TALK. Same pixel style as the language button; on narrow screens it stays visible (label can
  shorten to "▶ ASK"). It's a real button, reachable by keyboard.
- The trainer card gets a **TALK** action. It opens a game-style dialogue box under the card
  (thick border, Press Start 2P label `VITOR:`, Inter body text, blinking ▼/cursor), in the active
  palette (Nu Purple / Red Lantern).
- Mockups: `.superpowers/brainstorm/6711-1794512130/content/embed-options.html` and
  `talk-flow-v2.html` in this repo (git-ignored; local reference).

### States

| State | What the visitor sees |
|---|---|
| Opened | Greeting ("I'm a bot that knows Vitor's CV, projects and what he's been up to"), 3 suggested questions, a text input, one line: answers come only from this site, his CV and repos; questions are saved anonymously |
| Answering | Text types out as it streams, blinking cursor, STOP button |
| Answered | Answer, source tags, 2 suggested follow-ups |
| Unknown / off-limits | `I don't have information about that.` plus a hint of what it can answer and the site's contact link |
| Off-topic / injection | `I only answer questions about Vitor.` plus a suggested question |
| Rate limited | "I need a short break. Try again in a minute." |
| Service down | Says it can't answer now and links the CV; the rest of the page is unaffected |

Voice (my call): labelled `VITOR:` like a game NPC, but speaks about him in the third person and
says it is a bot. Short answers (1–3 sentences). On mobile the dialogue box is full width.
Keyboard and screen readers: `aria-live="polite"` on the answer, `role="alert"` on errors, focus
moves to the input when TALK opens, WCAG AA contrast in both palettes.

Everything in it is already public; the bot can't leak beyond it.

| Section | Source | Notes |
|---|---|---|
| Profile and CV | curriculum-vitae `main/` (private repo) exported to a public-safe summary; matches the public resume PDF and LinkedIn | Roles, dates, responsibilities, projects, skills, education. Every claim traces to `main/`. |
| Repos | GitHub API, public repos only | Name, description, README summary, main language, link |
| Live data | What `homepage/sources/` already fetches every 4h (Spotify, Strava, Letterboxd, Goodreads, MyAnimeList) | My call: only the latest item per source, as the site already keeps in its state, no history. ## How it runs

```
jvitorcosta.github.io (static, GitHub Pages)
  TALK dialogue (site.js) ── POST /ask/stream (SSE) ──► ask-vitor API on Vercel
                                                         │  loads knowledge.json from the site (cached)
                                                         ▼
                                                    Claude Haiku 5.5 (claude-haiku-5-5)
```

- **Model:** Claude Haiku 5.5 through the official Anthropic Python SDK, a new `AnthropicClient`
  implementing the existing `LLMClient` protocol (`chat` + `stream_chat`). Ollama stays as the
  local backend; a setting picks the backend.
- **Prompt:** the existing grounded prompt, extended: answer only from the knowledge file, 1–3
  sentences, cite source ids, fixed fallback, never-share list, off-topic reply, answer in the
  question's language. No temperature setting (Haiku 5.5 rejects non-default values, so the
  prompt and evals carry the consistency instead). Knowledge file in a cached system block (prompt caching) to
  cut cost and latency.
- **Hosting:** Vercel (like his Spotify server). CORS allows only the site's origin (and localhost
  for dev).
- **Cost:** a separate API key in its own workspace under his org ("Vitor's Individual Org", which
  includes $200/month API credit), with a **$5/month spend limit**. Expected ~$0.001–0.003 per question.
- **Abuse:** about 10 questions per visitor per hour; the IP is used only in memory for the count,
  never stored. Question length capped at 500 chars (existing). Max output tokens kept low.
- **Failure:** API down or over budget → the dialogue shows the service-down state; the page never
  waits on it (loads only when TALK opens).

## Fixed replies and how the UI knows them (my call)

The API doesn't make the UI match answer text. The final SSE `done` event carries
`{"kind": "answer" | "fallback" | "off_topic", "sources": [...]}`, and the UI picks the state from
`kind`. The fixed strings exist in both languages and the prompt uses the one matching the
question:

| kind | EN | PT |
|---|---|---|
| fallback | `I don't have information about that.` | `Não tenho informação sobre isso.` |
| off_topic | `I only answer questions about Vitor.` | `Só respondo perguntas sobre o Vitor.` |

The eval scorer accepts the fixed string of the question's language. The existing `/ask` JSON
contract keeps working.

## Logging (approved)

Store per question: question, answer, source ids, fallback flag, latency, date. Never: IP, user
agent, cookies, session id. Emails and phone numbers redacted before storage. Deleted after 90
days. The dialogue says "Questions are saved anonymously to improve answers".

Privacy page (my call): the site's `privacy.html` is currently the privacy policy for a Google
OAuth app, with one line about the site ("no cookies, analytics or tracking"). Leave that policy
alone and add a separate page for the website itself, linked from the dialogue and the footer.
It names the ask-vitor API on Vercel, Anthropic as the processor of the questions, the log store,
what is saved and for how long.

## Quality: evals and docs (ask-vitor repo)

- Extend `evals/questions.json`: personal facts, live data, every never-share category, location
  probing ("which gym?"), Portuguese questions, injection, false premises, off-topic. Score with the
  existing rule-based scorer; add a check that cited source ids exist.
- Run evals against Haiku 5.5 and record results like the existing model table.
- New study doc in `docs/` covering grounding, the fallback contract, citations, guardrails,
  privacy-by-design of the knowledge file, prompt caching, cost cap and rate limiting, logging.
- README updated (hosted mode, config, costs).

## Constraints

- Site: static GitHub Pages, build is Python stdlib only (`homepage/`), no tracking, WCAG AA,
  "never claim what the repo doesn't back up", EN/PT strings kept in step.
- Site work must not collide with other sessions working on the site. As of 2026-11-12 the
  Letterboxd "now watching" work has merged and the site's `main` is clean; check again for open
  branches or PRs before editing shared files (`assets/site.js`, `render.py`, `right_now.py`,
  `data/strings.toml`).
- Resume claims never go beyond curriculum-vitae `main/` (and its never-claim list).
- No secrets in either repo; API key lives in Vercel env vars.

## Left to the builder

- Storage for logs (e.g. a Vercel-friendly KV/Postgres) and how 90-day deletion runs.
- Rate-limit mechanism on serverless (in-memory per instance vs a small KV), as long as no IP is stored.
- How the CV export from the private repo reaches the site build (committed export file vs CI step),
  as long as only public-safe content leaves the private repo.
- Exact `knowledge.json` schema and source-id format.
- Suggested questions and follow-ups (static list vs model-proposed from a fixed set).
- Whether the TALK dialogue code lives in `assets/site.js` or a separate small script.
